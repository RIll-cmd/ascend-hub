### Cross-project contracts

- **Core is the status authority.** Producers report through Core's authenticated `POST /api/status/events`; readers use `GET /api/status/shelf`. Hub's server proxy reads that existing v1 API and keeps its dedicated read credential server-side.
- Status identities include `ascend-core`, `ascend-vision`, `codex-cli`, and `antigravity-cli`. Keep service identity and instance identity separate. The normalized states are `idle`, `working`, `stuck`, and `offline`.
- Producer heartbeat expiry is approximately 30 seconds. Hub ordinarily polls every four seconds and slows polling in hidden tabs. A successful UI refresh is not evidence of a fresh producer heartbeat. Missing telemetry, stale data, and media playback failure remain separate from lifecycle state.
- Core read credentials and producer credentials have different authority. Keep their scope separate from user sessions, Spotify credentials, weather keys, and AI-provider credentials.
- Codex CLI and Antigravity CLI reporting applies to sessions started through the wrappers in Hub's `scripts/status-adapters/`. **Antigravity IDE/sidebar reporting is unsupported.** Hermes and standalone bot adapters are not implemented in this integration.
- Vision UI readiness, chat readiness, AI-provider readiness, Core connectivity, camera, and microphone status are independent. Chat recovery intentionally lacks camera, microphone, gestures, focus sessions, and browser automation.
